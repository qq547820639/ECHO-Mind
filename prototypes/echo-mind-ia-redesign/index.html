01

执行摘要

用户反馈聚焦为四点：功能挤在同一个界面、没有清晰层级与分组、难找功能、易误操作。逐条溯源后，四点都指向同一个根因——Me 世界把「控制中心」错做成了「一页平面」：没有层级间的能量差，重内容与轻内容、日常项与危险项获得同等排版权重。

根因：一页平面的三个代价
空间记忆就地手风琴展开后，分组被推离视口、无 TopAppBar 与返回键，用户失去「我在哪、怎么回去」的锚点。
入口通胀同一主题最多三处入口（数据/权限、壁纸/屏保），入口之间互相稀释信任：「哪个才是真的？」
权重倒置280dp 纯装饰画布占首屏黄金区，危机入口以普通红行混排在中部；关键性没有变成视觉重量。
解法：两级渐进式披露
L0四分区 + 2×2 状态网格，滚动长度 ≤2 屏，每卡一行真实状态摘要。
L19 个全屏次级页（TopAppBar + 返回），复用 EchoAskScreen 已验证的导航范式。
D 区SENSING 页内四分区，数据权利独立为视觉隔离的危险区置底，删除保留强确认。
02

现状诊断 D1–D6

每条诊断附源码行号锚点（本地 file:// 链接，需在本机打开本页可点击），并给出可直接执行的一句话结论。

D1

就地手风琴破坏空间记忆与返回预期

expandedDomain 一次只展开一个域，域深页就地渲染在所属分组下方。重内容（数据与感知 ≈190 行）展开后整页滚动长度爆炸、其他分组被推离视口，且无 TopAppBar 与返回键——与产品内已有的正确范式（EchoAskScreen 全屏次级页 + BackHandler）不一致。

MeScreen.kt // §63：presentation state（一次只展开一个 domain；不建立新业务 state） var expandedDomain by rememberSaveable { mutableStateOf(MeDomain.NONE.name) } fun open(target: MeDomain) { ... }
MeScreen.ktL192-196expandedDomain 就地展开状态机 MeScreen.ktL378-397MeDomainDetail 域深页就地渲染于分组下方

结论轻内容可就地展开（Why 证据），重内容必须次级页。

D2

同一主题多入口（违反「一个概念一个家」）

数据/权限主题三处入口：① 智能地图组「数据与权限」→ DataOrbit（纯装饰）；② 「了解我的方式」组「数据与感知」→ 真实控制；③ 「我的数据」组导出/删除——且删除还要跨分组强制展开 OBSERVATION 域再弹确认，而 DataAndSensingSection 内部本就有完整的数据权利块。壁纸/屏保同样双入口（L0 行 + PresenceSettingsSection 内部按钮）。

MeScreen.kt // 删除确认对话框在数据与感知分节内呈现：强制展开该分节再触发删除流程 expandedDomain = MeDomain.OBSERVATION.name actions.onDeleteData()
MeScreen.ktL216-221入口①：「数据与权限」→ 纯装饰 DataOrbit MeScreen.ktL287-305入口③：「我的数据」导出/删除 + 跨分组强制展开 DataAndSensingSection.ktL254-281域内已有的完整数据权利块（导出/删除/撤回） PresenceSettingsSection.ktL85-106壁纸/屏保第二入口

结论入口必须去重：数据权利唯一入口 = SENSING 页 D 区；壁纸/屏保唯一入口 = PRESENCE 页。

D3

装饰内容占用黄金区且零可供性

SmartMap 与 DataOrbit 两张 280dp Canvas 的节点与 Chip 均不可点；「快速管理」行与 4 张设置卡传入 emptyList() 占位——标题仍在，内容为空。视觉耗费了用户最多的注意力，却不承载任何信息或可供性。

MeScreen.kt MeSmartMapSection(devices = SmartMapDevices(...), quickAccessItems = emptyList()) DataPermissionOrbitSection(nodes = listOf(...), cards = emptyList())
MeSmartMapSection.ktL182-192快速管理 5 入口实际为 emptyList 占位 DataPermissionOrbitSection.ktL104-1124 设置卡 emptyList 占位

结论视觉必须承载信息或可供性，否则降级为小尺寸入口卡或退役（DataPermissionOrbitSection.kt 整文件删除）。

D4

数据与感知域 9 类主题平铺（信任中心变杂物间）

consent 总控 / 4 权限行 / 观测文本 / 立即同步 / 麦克风（二次确认）/ 本机面板 / 数据权利（导出/删除/撤回）/ 身份 / 免责，约 190 行全部同级连续渲染。危险操作与日常开关之间没有任何视觉分离——「删除本机数据」和「每晚小结提醒」长得一样重。

DataAndSensingSection.ktL99-2889 类主题连续渲染：开关→权限→观测→同步→麦克风→面板→数据权利→身份→免责

结论域内需要二级分区（A 总控与节奏 / B 感知通道 / C 本机面板 / D 数据权利）+ 危险区视觉隔离。

D5

次级拥挤

WristSection 单卡塞入 8 个功能点（Device / Connection / availability / 佩戴 / 睡眠 / 运动 / 触觉 / Privacy），虽有 Advanced 折叠但一级仍全部平铺。JourneyScreen 的趋势内容尾部硬编码追加成长页（onContinueClick = {} 空实现），两个主题挤一屏，免责声明夹在中间。

WristSection.ktL44-226单卡 8 功能点连续平铺 JourneyScreen.ktL144-174成长页无条件追加在趋势尾部

结论手环页整合为「状态头卡 + 偏好 + 连接管理 + 高级折叠」；Journey 顶部「趋势 | 成长」分段切换，不再追加。

D6

优先级倒置：危机入口埋在首屏中部

危机入口（全 App 关键性最高的元素）以一条普通红行混排在首屏中部；而它上方，是两张 280dp 的纯装饰画布。排布顺序传达的优先级与功能的关键性完全相反。

MeScreen.ktL226-234「紧急支持」红行位于智能地图组之后、了解我的方式组之前

结论安全常驻 + 归入 Z3「支持与安全」分区并保持行首位置；全局紧急 FAB 行为不变（不变量 1）。装饰画布退役后，关键路径上方不再有噪声。

06

渐进式披露原则

五条原则构成裁剪每个新增功能时的判据——先问层级，再问排版。

一L0 保持 ≤2 屏

L0 是「控制中心」不是「内容页」。任何新功能先问：它的状态摘要能否用一行说清？能 → 进状态卡；不能 → 它属于某个 L1 页。

判据：L0 新增任何行之前，先数 Z1–Z4 之外还有没有东西

二重内容进次级页，轻内容才就地

预期超过一屏、或含表单/弹层/危险操作的内容一律 L1 全屏页（TopAppBar + 返回）。只有 1–2 行的轻内容（如一条免责说明）允许就地展开。

判据：滚动长度是否会因展开而翻倍

三危险区隔离、置底、强确认

导出/删除/撤回与日常开关永不同级同貌：独立分区、红色描边、置于页面底部，删除需勾选强确认。路径收敛到一个入口（SENSING 页 D 区）。

判据：误触的最大代价是否不可逆

四视觉必须承载信息或可供性

280dp 装饰画布不可点、占位 emptyList() 的区块一律退役或降级为小尺寸入口卡。智能地图保留，但移入 SMARTMAP 页并让快速管理行指向真实功能。

判据：点按它会发生什么——答不出来就删

五认知负荷随层级递减

L0 读「状态」，L1 读「控制」，L2（折叠/Advanced）读「诊断」。每一层的信息密度和措辞专业度逐层上升，默认层永远是最安静的。

判据：首屏出现的文案里有没有超过一行的术语
07

不变量与落地边界

重构期间绝不破坏的六条约束（与 spec 一致）；原型已按此设计交互。

  • 安全常驻全局紧急 FAB 与 shouldShowEmergencyFab 不变；Me-Z3 紧急支持行直达全屏 SafetyScreen，IA 精简绝不隐藏安全资源。
  • testTag 契约me_entry_* 系列锚点全部保留，语义不变，宿主允许换父容器。
  • 无障碍48dp 触达、图标 + contentDescription 双语义、Role.Tab / Role.Button、导航态 rememberSaveable。
  • 业务状态零改动MeUiState / MeViewModel / DataAndSensingViewModel / WristViewModel 状态装配不动，仅 presentation 层重排。
  • 视觉语言V3 §48 安静三世界规范（near-black .92、identity glow、warm accent）与 EchoMindTheme 令牌不变。
  • 架构边界仅动 ui/ 展示层与测试；不引入 Navigation-Compose 新依赖，沿用状态切换范式。
08

交互原型

在浏览器里走一遍新的 Me 世界

原型以 390×844 手机框架呈现：L0 四分区、2×2 状态网格、9 个 L1 全屏页、SENSING 四分区与危险区全部可操作——开关、折叠、弹层、强确认、hash 路由保持当前页。支持有数据态与空态切换。
