## 0. 一句话结论（必须先读）

**"被动感知范式全量落地"在端侧是"半落地"：Collector→FeatureExtractor→saveDerivedFeature→Outbox→SyncWorker→后端 的整条链在生产代码里没有调度器、没有触发点、没有任何一个生产调用方。** 端侧所有被动感知能力（5 分钟窗口、特征提取、麦克风派生特征上传、通知数据共享）目前只存在于"类定义 + 单元测试"，App 运行时不会产生任何一条派生特征。后端 /v1/features/ingest、/v1/narratives、/v1/profile 等服务是完整可用的，但由于端侧不上行数据，后端画像/叙事/沙箱/Skill 下发全部是"空转"。

次要结论：后端存在 4 类 P0 工程/安全缺口（GET 读副作用、feature flag fail-open、sandbox timeout 无效、audit 并发分叉），以及一批 P1/P2 契约与一致性问题（source 契约错位、skill 非 signed-only、sensor_samples 表残留、CORS 缺 PUT/PATCH、DSR 删除矩阵不完整、版本号文档漂移等）。

【真实数据流证明】
- 后端沙箱回路完整：schedule→runner→五步造工具→Skill(draft)→transition 手工评审→signed→GET /v1/skills 脱敏下发。
- 正向点：sanitizer 过滤了原始特征引用与内部 ID；Skill 状态机禁止跳级。

【缺口/断裂点】
- **P0-B3a（sandbox timeout 无效）**：`future.result(timeout=120)` 抛 TimeoutError 后，`with ThreadPoolExecutor` 的 `__exit__` 会执行 `shutdown(wait=True)` **阻塞等待 worker 线程结束**——若 worker 死循环/挂起，请求线程无限阻塞，超时形同虚设；若 worker 稍后完成，又会与主线程 `_record_failure` 竞态写同一 `SandboxRun` 行。
- **P0-B3b（无资源配额/隔离）**：`_run_loop` 在**请求进程内线程**执行任意 Python 代码，无 CPU/内存/网络配额、无子进程/容器隔离；`schedule_sandbox_run`（scheduler.py L66-89）的并发信号量只在"调度"瞬间持有（L88 finally 释放），**不覆盖执行期**，"并发 4"限制无效。
- **P1-B3c（source 契约错位）**：gap_finder 期望每 source 独立的 DerivedFeature；而端侧每窗口只产出一个 source（A3）→ 沙箱持续误报缺源。
- **P1-B3d（Skill 非 signed-only）**：`DELIVERABLE_SKILL_STATUSES` 含 `reviewed`，`reviewed` 状态即可下发，非 signed-only；retire 无客户端失效推送（客户端仅靠 SharedPreferences 缓存 TTL 1h + 拉取时 status 过滤，最坏 1 小时滞后）。
