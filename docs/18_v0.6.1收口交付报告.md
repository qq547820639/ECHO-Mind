## 2. 每项问题：根因 / 方案 / 测试 / 风险

### P0-2 人工支持客户端闭环
- **根因**：后端已有完整 escalation 状态机与 `POST /v1/escalations`，SyncWorker 也有 `escalation` 类型映射，但 Android 无任何创建 escalation 的用户调用链（SupportScreen 只有拨号按钮）。
- **方案**：`LocalRepository.requestHumanSupport()`（event_id → 本地 `escalation_requests` 表 → Outbox → 网络恢复 POST，幂等）；SyncWorker 成功后回写 serverEscalationId + DELIVERED；支持页「请求机构支持」按钮 + 二次确认 + 五态展示（等待送达/已送达/人工已确认/正在接管/已完成）；`refreshEscalationStatus` 用 user-status 端点，**只有服务端 human_acknowledged 才进入接管态**。
- **测试**：`offlineEscalationQueuesToOutboxWithQueuedStatus`、`escalationAckLifecycleReflectsServerStatusOnly`（未 ACK 不显示接管）。
- **风险**：真机 ACK→takeover 端到端待机构值班演练验证。

### P0-3 consent/sensing/revocation 唯一状态机
- **根因**：「撤回同意并停止服务」按钮只提交 DSR，不停止服务/不清 buffer/不关 mic；OFF→ON 不产生 granted 证据，服务端最新 consent 仍 revoked → feature ingest 持续 412（KEEP_PENDING 10 次后 dead-letter）；无等待授权 UI。
- **方案**：`ServiceRevocationCoordinator.revokeService()` 原子协调 9 步（OFF/关麦/stop/清缓冲/三份 revoke 证据/DSR/UI/同步），幂等位 `serviceRevocationSubmitted`；`reEnablePassiveSensing()` 先入 granted 证据（priority 600 > feature 20）再启动服务，`consentSyncPending` 标记「正在重新启用 · 等待授权同步」，SyncWorker 收到 consent 2xx 后清除；支持页总开关与数据权利按钮统一走协调器。
- **测试**：revoke 停止+证据、重复撤回幂等、re-enable 顺序（consent 先于 feature）、consentSyncPending 生命周期。
- **风险**：consentSyncPending 为普通 SharedPreferences 位，UI 刷新依赖重组时机。

### P0-4 Skill Active Session 一致性
- **根因**：sessionId 由 `remember { UUID.randomUUID() }` 每次重建生成，进程死亡恢复后 completion 用新 sessionId 删不掉真实会话行；每张卡独立 `loadActiveSession()` + 非本卡即删除（跨卡误删）；DAO `LIMIT 1` 随机取。
- **方案**：`SkillSessionCoordinator` 统一生命周期（Mutex 串行化）；恢复按 skillId 精确查询且**沿用原 sessionId**（restoreFrom 后不重新生成）；start 前收口旧会话（single-active 双重强制）；finish 按真实 sessionId 删行 + completion 幂等；渲染器动作全部回调上抛。
- **测试**：`processDeathRestoreKeepsOriginalSessionId`、`multiCardDoesNotDeleteOtherSkillsSession`、`singleActiveSessionEnforcedOnStart`、`repeatFinishIsIdempotentViaCompletionEventId`。
- **风险**：进程死亡后恢复为 PAUSED 不自动计时（设计如此，防虚增）；真机重组/杀进程需真机验证。

### P0-5 ActivationCode
- **根因**：`verify_onboarding_code` 直接 `User.external_ref == code` 跨租户扫描——外部引用隐式承担生产激活凭证。
- **方案**：`ActivationCode` 表（code_hash 全局唯一/TTL/used_at 一次性/attempt_count/max_attempts）+ `activation_attempts`（IP/device/code 三维 rate limit + 审计）；兑换用 `UPDATE ... WHERE used_at IS NULL RETURNING` 原子消费；统一 404/403 文案不泄露存在性；admin 签发/列表/吊销端点；明文码仅在签发响应出现一次；external_ref 回退保留并标记 v0.8 退役。
- **测试**（13 项）：跨租户同 external_ref、collision、expired、revoked、replay、**8 线程并发消费恰一次成功**、brute-force、IP 限流、restricted user、端到端签发→兑换→replay 403、admin 权限。
- **风险**：rate limit 计数为数据库行数（窗口 15 分钟）；生产建议叠加网关级限流。

### P1-6 Sync 状态语义
- **根因**：`lastSyncTimestamp` 一个时间戳同时表达尝试与成功（SyncWorker 每批结束都写）。
- **方案**：拆分 `lastSyncAttemptAt`（批开始）/`lastSuccessfulSyncAt`（仅无遗留且无失败）/`lastPartialSyncAt`/`lastSyncErrorClass`（分类而非原始异常）/`pendingCountSnapshot`；UI 文案更新（最近成功同步/等待网络/N 项待同步/部分未同步/需要重新授权/失败可重试）。
- **测试**：`partialBatchClassification` 覆盖 success+429/412/5xx/dead-letter/全部成功/offline 分类。
- **风险**：旧 `lastSyncTimestamp` 读取点已全部改为成功语义；如漏改会显示错误时间（已 grep 确认）。

### P1-7 Onboarding 可恢复状态机
- **根因**：finishOnboarding 直接置 READY_OFFLINE，SyncWorker 无 READY 收敛逻辑；重复点击会重复入队 consent/L0。
- **方案**：`onboardingLocalSubmitted` 幂等位（重复提交直接推进）；SyncWorker 批清空后调用 `confirmServerActivation()`（GET consents/latest 核对心理同意 grant + 被动感知与本地一致 → serverActivated=true + READY）；步骤恢复依赖 onboardingState（已有）+ 新幂等位。
- **测试**：`readyOfflineConvergesToReadyAfterServerAck`。
- **风险**：服务端核对依赖网络；离线保持 READY_OFFLINE 是正确语义。

### P1-8 Trend 七态真实接入
- **根因**：`systemBackgroundRestricted = false`、`missingSources = emptyList()` 占位；PERMISSION/CLOSED/SERVER_UNAVAILABLE 三个枚举不可达。
- **方案**：电池优化豁免（isIgnoringBatteryOptimizations）+ collector heartbeat（>3 天无采集视为停滞）真实驱动 SYSTEM_BACKGROUND；`profile.sourcesPresentUnion` 与 EXPECTED_CORE_SOURCES（accel/gyro/screen/notification/app_activity）对比驱动 SOURCE_GAPS；consent/permission 输入驱动 CLOSED/PERMISSION；**删除不可达的 SERVER_UNAVAILABLE**。
- **测试**：`trendNoDataReasonsAllReachable`（8 态全覆盖）。
- **风险**：电池优化 API 在部分厂商 ROM 返回值不可靠（真机矩阵验证项）。

### P1-9 趋势语义收紧
- **根因**：`activityRhythmSummary` 用数据存在性包装成"活动量高低"；TrendContent 直接显示 `accel/gyro/app_activity` 内部码。
- **方案**：文案改为「活动传感数据覆盖」（明确不代表活动量高低）；`SOURCE_DISPLAY_NAMES` 映射人类可读名，内部 code 不出现在普通 UI（未引入 debug 界面，code 已不再展示）；README 非诊断边界不变。
- **测试**：现有文案锚点测试（TREND_DISCLAIMER 等）未破坏。
- **风险**：无。

### P1-10 Sandbox 并发配额
- **根因**：并发检查只在 schedule 阶段 count running（check-then-act）；`acquire_tenant_slot/release_tenant_slot` 已废弃恒 True。
- **方案**：`sandbox_tenant_slots` 表（tenant_id PK/running_count/heartbeat_at），`UPDATE ... SET running_count+1 WHERE running_count < max RETURNING` 行级原子；runner.execute() 执行期 acquire（失败 → failed 不占配额）+ finally release（completed/failed/timeout/异常统一）；心跳 15 分钟过期回收（worker crash）；pending 与 running 分离。
- **测试**（7 项）：12 线程并发恰放行 max 个、release 递减、stale 回收、runner 释放、并发满时直接 failed、timeout 路径释放、pending/running 分离。
- **风险**：PG job 复用同一 UPDATE 语义（本机无 PG，CI 覆盖）。

### P2-13 routes.py 拆分
- **根因**：1910 行单文件，混合所有领域。
- **方案**：按 bounded context 拆 11 个子 router + `deps.py` 共享依赖；routes.py 降为聚合器；URL/OpenAPI 完全不变（契约测试验证）。
- **测试**：全量 923 项回归 + `test_openapi_contains_all_v1_routes`（实时导出对比）。
- **风险**：低（函数体原样迁移；monkeypatch 路径适配 1 处）。

### P2-14 机构工作台
- **根因**：list 全表加载、metrics 全表加载到 Python。
- **方案**：keyset cursor 分页（limit/cursor/status/level/assigned_to 过滤；`X-Next-Cursor`/`X-Total-Filtered` 响应头，**body 保持数组契约**）；metrics 用 SQL 聚合（COUNT + GROUP BY status + AVG 时长下推）。
- **测试**：test_workbench_v03 全过（7 项）+ 新分页参数不破坏旧断言。
- **风险**：平均时长近似 p50（精确分位由 analytics 层处理，注释说明）。

### P2-16 可观测性
- **根因**：无结构化遥测。
- **方案**：`services/telemetry.py` 结构化日志（request_id/method/path/status/duration_ms + ingest 拒绝分类计数）；中间件接入；**禁止记录**原始传感/token/journal/明文 consent/加密前心理数据（文档声明）。
- **测试**：遥测中间件随全量测试运行无回归。
- **风险**：无。

## 4. 旧调用链 → 新调用链

**人工支持**：`(无入口)` → `SupportScreen「请求机构支持」→ requestHumanSupport() → escalation_requests + Outbox → SyncWorker → POST /v1/escalations → 回写 DELIVERED/serverId → user-status 轮询 → TAKEN_OVER`

**撤回服务**：`两套半实现（总开关 performPassiveSensingStop / 数据权利按钮只发 DSR）` → `ServiceRevocationCoordinator.revokeService() 唯一入口（9 步原子）`

**Skill 会话**：`SkillCardHost 内 remember + 每卡独立 load/delete` → `SkillSessionCoordinator（single-active + 原 sessionId 恢复 + 按 skillId 精确读写）`

**激活**：`verify-code 直查 User.external_ref` → `redeem_code（ActivationCode 原子消费）→ legacy 回退（v0.8 退役）`

**同步状态**：`lastSyncTimestamp 单时间戳` → `attempt/success/partial/errorClass/pending 五字段`

**Onboarding**：`finishOnboarding 直接 READY_OFFLINE（无收敛）` → `SyncWorker 批清空 → confirmServerActivation（服务端 consent 核对）→ READY`
