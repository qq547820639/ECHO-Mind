# 权限矩阵 v0.6.2（Batch A）

> 逐行依据真实代码验证（`grep` 于 `android/app/src/main`），不得编造。
> 生成时间：v0.6.2 Batch A（Collector 单一数据源 + SyncWorker 状态机强化 + 权限清理）。
> 目的：让「声明了什么权限、代码在哪里用、是否可延迟/撤销」可审计。

## 一、权限清理结论（v0.6.2 已删除）

以下 5 项权限在 **Manifest 之外零代码使用**（`grep` 全仓含 `res/xml` 确认），已从
`android/app/src/main/AndroidManifest.xml` 删除：

| 权限 | 原 Manifest 位置 | 代码使用点 | 删除理由 |
|---|---|---|---|
| `ACTIVITY_RECOGNITION` | 步数/身体活动识别 | 无任何 Sensor.TYPE_* 识别/计步 API | 零使用 |
| `HIGH_SAMPLING_RATE_SENSORS` | 传感器声明 | 无任何 registerListener 高采样率（始终 SENSOR_DELAY_NORMAL） | 零使用 |
| `WAKE_LOCK` | 保持唤醒 | 无 PowerManager.WakeLock / FLAG_KEEP_SCREEN_ON | 零使用 |
| `FOREGROUND_SERVICE_REMOTE_MESSAGING` | 前台服务声明 | 无 RemoteMessaging 相关 API | 零使用 |
| `BODY_SENSORS` | 传感器声明 | 仅 `PassiveSensingService.canStartSensing` 门禁检查（已一并删除） | 加速度/陀螺仪为**普通传感器**，Android 12+ 不需要该权限（它保护心率等医学类传感器）；保留会让「允许身体传感器」开关与采集行为脱节 |

删除后门禁变为：**consent + 租户 flag + POST_NOTIFICATIONS + 通知使用权 + 使用情况访问**（`PassiveSensingService.passiveSensingGatePasses`）。

## 二、保留权限矩阵

### 1. `INTERNET`

| 项 | 值 |
|---|---|
| Manifest | `AndroidManifest.xml`（application 级，无 tools:ignore） |
| 实际 API 使用位置 | `data/ApiClient.kt:34,55,77,102`（`URL(...).openConnection()`）；`data/SyncState.kt:59`（`NET_CAPABILITY_INTERNET` 探测） |
| 功能 | 全部上行（outbox 同步 / skill 下发 / 叙事拉取 / verify-code）与状态探测 |
| 必须性 | 必须（无网络则产品不可用） |
| 可否延迟 | 否（核心功能前提） |
| 用户解释 | 用于机构服务同步与数据上传；所有上传均为结构化派生特征/consent 证据，不传原始音频/传感器原始样本 |
| 撤销降级 | 撤销后离线运行：数据留本机，`OFFLINE` 态展示；恢复后自动补传 |

### 2. `POST_NOTIFICATIONS`（API 33+ 运行时权限）

| 项 | 值 |
|---|---|
| Manifest | `AndroidManifest.xml`（前台服务通知） |
| 实际 API 使用位置 | `sensing/PassiveSensingService.kt:124`（门禁检查）；`:207`（通知渠道创建）；前台服务通知展示依赖它 |
| 功能 | 被动采集持续通知（`buildNotification`，`PassiveSensingService.kt:205`） |
| 必须性 | 必须（前台服务通知为系统强制可见性 + 门禁 fail-closed 条件） |
| 可否延迟 | 可延迟（采集前由系统在 FGS 启动时引导；门禁在未授权时阻止采集，fail-closed） |
| 用户解释 | 用于显示「被动采集中（端侧处理）」的常驻通知 |
| 撤销降级 | 门禁 `postNotificationsGranted=false` → 不启动采集（fail-closed）；已有采集数据保留待权限恢复 |

### 3. `PACKAGE_USAGE_STATS`（特殊权限，需系统设置授权）

| 项 | 值 |
|---|---|
| Manifest | `AndroidManifest.xml`（`tools:ignore="ProtectedPermissions"`） |
| 实际 API 使用位置 | `sensing/AppActivityCollector.kt:25`（`getSystemService(Context.USAGE_STATS_SERVICE)`）；门禁 `PassiveSensingService.kt:250-269`（`AppOpsManager.OPSTR_GET_USAGE_STATS` 授权检查） |
| 功能 | 记录前台 App 切换（仅时间戳 + 包名，不记录 App 内内容） |
| 必须性 | 可选核心信号源（`app_activity` 属 EXPECTED_CORE_SOURCES） |
| 可否延迟 | 可延迟（采集开始前引导用户到系统设置「使用情况访问」） |
| 用户解释 | 用于记录你打开了哪些应用（仅统计切换次数/最常使用应用时长，不读取内容） |
| 撤销降级 | 撤销后 `hasUsageAccess=false` → 门禁 fail-closed 停止采集；已收集特征保留在本地，可继续上传 |

### 4. `RECORD_AUDIO`（危险权限，运行时请求）

| 项 | 值 |
|---|---|
| Manifest | `AndroidManifest.xml`（T03 麦克风可选模块） |
| 实际 API 使用位置 | `sensing/MicCollector.kt:198`（权限检查）；`ui/OtherScreens.kt:537`（`ActivityResultContracts.RequestPermission` 运行时请求）；`:497`（launcher 构造）；`MicCollector.kt:139`（录音循环内周期性权限撤回检查） |
| 功能 | 可选麦克风派生特征（音量/语速/停顿/基频）；**原始音频即时处理后丢弃，绝不落盘不上云** |
| 必须性 | 可选（默认关闭 `micEnabled=false`） |
| 可否延迟 | 可延迟（用户主动开启麦克风开关时才请求） |
| 用户解释 | 仅本地提取音频特征（音量/语速/停顿/基频），不记录、不上传录音内容 |
| 撤销降级 | 系统设置撤回后：`MicCollector` 录音循环检测到权限丢失 → 立即停止 + 写 `voice_features` consent（granted=false）证据 + 触发同步（`PassiveSensingService.kt:70-81` 回调链） |

### 5. `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE` + `specialUse` property

| 项 | 值 |

## 三、隐私不变量复核（权限相关的硬约束）

- **原始 sensor 样本 / 音频 / 屏幕 / App 使用明细 不落盘不上传**：样本仅存于进程内
  `SensingEventHub`（Batch A 单一数据源收敛后，collector 无本地缓冲），窗口 flush 时经
  `FeatureExtractor` 聚合为 `DerivedFeatureInput`（summary + ≤256 维 vector）后落库+上传。
- **通知正文不入库**：`NotificationCollector.NotificationMeta` 仅 3 字段
  （`timestamp/packageName/category`），SensingEventHubTest 有编译期+运行时双断言。
- **隐私 flag fail-closed**：`passive_sensing_enabled` 无缓存默认 false（`AppPreferences.defaultFlags`）。
- **BODY_SENSORS 移除后无医学类传感器权限**：与「行为派生特征、不读取健康数据」的产品定位一致。
