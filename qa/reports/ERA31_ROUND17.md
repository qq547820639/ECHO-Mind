# ERA 31 Round 17 报告（Ask ECHO 免费用户走查：AI 催促清零 + 问法归一）

> 日期：2026-08-15。

## 走查发现

以「无 AI 免费用户」身份走查 Ask ECHO（ERA 34 核心产品价值 + gate #5/#9），发现四处真实缺陷：

1. **界面建议的问题答不了**：Ask ECHO 卡片建议「为什么今天 ECHO 看起来不一样？」，但该问法
   不在 PersonalAnswerEngine 覆盖表 → 用户照着建议问 → 兜底文案「还没有连接 AI，或者当前没有网络。」
   → 产品被免费用户判定为「没连 AI 的残废 demo」，建议问题成了诱饵。
2. **AI 催促 + 网络泄漏兜底**：引擎未收录 + 无 Provider 时返回
   「我现在还不能回答这个问题：还没有连接 AI，或者当前没有网络。」——每问一次就提醒一次
   「你没连 AI」（免费用户常态）+ 网络状态属工程细节（gate #9 更安静而不是更吵）。
3. **逐字匹配脆弱**：引擎对问题做精确字符串匹配——用户加「了」、半角问号、感叹号、
   不带标点就命中不了（如「最近我是不是越来越晚了?」），直接掉进 #2 的催促文案。
4. **Me 能力边界暗示次等**：「还没有连接 AI：ECHO 不会生成 AI 解读，只用本地的确定性解释。」
   ——「只用」把确定性回答（R3 起 26/26 Core Set 全部本地可答）暗示成降级品。

## 修复

1. **视觉问题入表**：「为什么今天 ECHO 看起来不一样？」→ WHY_TODAY 族（语义同源：
   今天 ECHO 的视觉差异 = 今天最强的节律差异维度，正是 Why 层 headline 的解释对象）。
   离线确定性即可回答，界面建议不再落空。
2. **兜底文案 ECHO 化**：「这个问题我现在还确定不了。你可以换一种问法，比如：
   「最近我是不是越来越晚？」「今天的状态和平时有什么不同？」」——零 AI 催促、零网络状态
   泄漏、指向真实可答的问法。
3. **问法归一化**：句末语气词/标点（吗/呢/啊/呀/吧/嘛/了 + 中英文 ？！。，~）对表键与
   输入**同侧**剥离后建索引——用户微调措辞命中同一族；两个问题归一化后撞车会在类初始化
   时 `check` 直接失败（安全网而非静默覆盖）。
4. **Me 能力边界行中性化**：「没有连接 AI：解读基于你手机本地的确定性解释。」
5. EchoSceneUiState 注释同步（清理 R15 已移除提示的引用）。
